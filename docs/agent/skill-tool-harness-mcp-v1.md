# 가현봇 Skill · Tool · Harness · MCP 사용 체계 v1

## 목적과 현재 범위

사용자 문제를 해결하는 절차를 버전이 있는 실행 자산으로 쌓는다. 대화 기억, 진행 중인 일의 상태, 재사용 가능한 해결 절차를 서로 구분한다.

2026-10-04 사용자 승인 후 `DefaultAgentRuntime.runLoop`에 연결했다. `GAHYEON_AGENT_SKILLS_ENABLED=true` 또는 `gahyeon.agent.skills.enabled=true`일 때 스킬 Harness를 사용한다. 기본값은 false다. 승인·취소·재개는 기존 실행 원장을 사용한다. 운영 배포나 외부 계정 연결은 수행하지 않았다.

## 구성과 책임

- `AgentSkillCatalog`: 패키지 색인에 명시된 released 버전만 로드한다. manifest와 SKILL.md의 SHA-256을 함께 계산한다. 대화/도구 결과에서 스킬을 설치하지 않는다.
- `AgentToolRegistry`: 네이티브 또는 MCP 출처, 도구 콜백, ALLOW/REQUIRE_APPROVAL/DENY, 사용자와 작업 범위 권한을 보유한다. 스킬은 이 권한을 확대할 수 없다.
- `AgentSkillHarness`: 실행마다 별도 상태를 생성한다. 선택 후 도구 집합 제한, 호출 예산, 근거 수집, 완료 전제 검사를 담당한다.
- `LedgerAgentSkillJournal`: 기존 agent_run_events에 선택, 시도, 근거, 검사 결과를 저장한다. 새 상태 DB나 별도 실행 원장을 만들지 않는다.
- `McpSkillToolAdapter`: Spring AI 1.0.1 BOM의 MCP SDK 0.10.0 클라이언트를 사용한다. 도구를 발견했다고 자동 허용하지 않는다. 로컬 승인 별칭·설명·스키마·권한으로 바인딩한다.
- `AgentSkillHarnessFactory`: 명시적 기능 활성화가 있는 경우에만 요청의 actor/toolScope와 허용 도구를 결합한다.

## 스킬 패키지

위치: `src/main/resources/agent-skills/<id>/<version>/`

- `manifest.json`: 사용자 문제, 적용 상황, 허용 도구, 필요한 도구 근거, 호출 예산, 완료 기준.
- `SKILL.md`: 실제 절차와 예외, 하지 못하는 일, 결과 판단 기준.
- `agent-skills/index.json`: 이 배포에서 선택할 수 있는 검토된 버전 목록.

id/version은 불변이다. 수정 시 새 버전을 추가한다. 재개에 필요한 이전 버전을 유지한다. 같은 버전의 내용이 바뀌거나 필요한 권한이 없어지면 재개를 거부한다. 롤백 때도 이전 버전을 보존한다.

첫 스킬 `outing-weather@1.0.0`은 외출을 앞두고 날씨에 맞춰 준비를 조정하는 작은 예제다. 새로운 사용자 수요가 검증되었다는 뜻은 아니다. 기존 도구로 전체 계약을 시험하기 위한 기준 사례다. 장소·날짜가 없는 요청에는 먼저 필요한 정보를 질문한다. 예보가 없는 결과를 성공 근거로 기록하지 않는다.

## 실행 계약

1. 사용자 문제와 적용 상황에 맞는 스킬 목록을 모델에 제공한다. 단순 대화는 기존 도구를 계속 사용할 수 있다.
2. 모델은 `agent_skill_select(id, version)`으로 명시적으로 선택한다. 선택 전에는 원격 도구를 노출하거나 호출하지 않는다.
3. Harness는 모든 의존 도구의 사용자/범위 권한을 확인하고 스킬 버전/해시를 기록한다. 선택한 절차를 모델에 반환한다.
4. 매 모델 단계마다 콜백 목록을 다시 생성한다. 스킬 선택이 포함된 한 응답에는 다른 도구를 섞지 않도록 공통 실행 루프가 강제한다.
5. 호출 직전에 Harness 결정과 기존 승인·취소 제어를 모두 통과한다. REQUIRE_APPROVAL은 기존 AgentApprovalService에서 정확한 도구/인자로 승인 소비 후 실행한다.
6. `beforeCall`로 시도를 기록한다. 도구를 실제 호출하고 취소 여부를 재확인한 뒤 `completed`로 결과 해시를 기록한다. 실패한 시도도 예산을 소모한다.
7. 최종 응답 전에 필수 근거 누락을 검사한다. 부족하면 모델에 알리고 기존 step 한도 안에서 보완한다. 보완하지 못하면 미완료로 종료한다.
8. 검증되지 않은 최종 답변이 음성/스트림으로 먼저 전달되지 않도록 활성화된 경로는 동기 모델 호출로 결과를 모으고 검사 후 AgentResult로 반환한다. 따라서 활성화된 요청은 토큰 스트리밍이 없고 최종 답변이 한 번에 전달된다. 비활성 경로의 스트리밍 동작은 유지한다.
9. `verifyCompletion`은 기존 `commitIfActive` 안에서 succeed 직전에 호출한다. 취소된 실행에 성공을 기록하지 않는다.

`verified`는 필수 도구 실행 근거가 모였다는 의미다. 사실 정확성, 계획의 실효성, 사용자 문제의 실제 해결을 보증하지 않는다. 첫 버전은 알려진 빈 결과/예보 없음/MCP 오류를 거부한다. 도메인을 확장할 때 구조화된 결과와 해당 도메인의 완료 검증기를 추가해야 한다. 임의 문자열의 의미를 만능 검증기로 판별하지 않는다.

승인 후 재개는 버전·호출 예산·근거 해시를 복원한다. 원본 도구 결과나 전체 모델 대화를 이 모듈이 복원하지 않는다. 기능을 비활성화한 상태에서 중단된 스킬 실행을 재개하면 기존 경로로 우회하지 않고 실패한다. 기존 런타임의 재개 방식은 별도 제약이며 쓰기 작업의 exactly-once 실행을 보장하지 않는다. 첫 스킬은 읽기 전용이다.

## MCP 연결과 권한

연결의 수명·타임아웃·인증은 명시적으로 구성한 `McpSyncClient`가 소유한다. 초기화된 클라이언트와 다음의 로컬 Grant로 `McpSkillToolAdapter`를 생성하고 `ApprovedMcpTools` 빈으로 등록한다.

- 서버 식별자와 충돌하지 않는 모델 노출 별칭
- 실제 서버 도구 이름
- 로컬에서 검토한 설명과 inputSchema
- ALLOW / REQUIRE_APPROVAL / DENY
- 허용 actor ID 집합과 정확한 toolScopeId

서비스 공용 자격증명을 모든 사용자에게 제공하지 않는다. 개인 계정 연결은 계정별 클라이언트와 Grant 수명·철회 구현이 추가로 필요하다. OAuth 계정 연결 UI, MCP 서버 자동 설치, stdio 명령 자동 생성은 이번 범위에 없다.

호출마다 tools/list에서 허용한 도구의 존재와 스키마를 확인한다. 목록 페이지는 최대 16개이며 반복 cursor는 실패한다. 변경된 스키마는 재검토 전까지 호출하지 않는다. 원격 설명이나 server instructions를 시스템 지시로 채택하지 않는다. MCP isError, 비텍스트 결과, 빈 결과, 64,000자 초과 결과를 거부한다. 전송 규약을 자체 구현하지 않고 프로젝트 BOM과 호환되는 SDK에 맡긴다.

## 해결 경험을 스킬로 축적하는 절차

1. 실제 사례에서 사용자 상황, 기존 대처, 어려움, 해결됐다고 판단할 조건을 확인한다. 개인정보를 일반 스킬 본문에 넣지 않는다.
2. 수행 결과를 보고 재사용할 절차를 후보로 추출한다. 한 번의 성공이나 모델의 자체 평가만으로 released에 올리지 않는다.
3. 후보에는 필수 맥락, 권한, 예외, 실패 시 행동, 완료 기준, 검증 사례를 함께 작성한다. 후보는 색인에 등록하지 않는다.
4. 누락 입력, 도구 실패, 권한 거부, 취소, 재개, 근거 없는 완료 주장에 대한 테스트를 통과시킨다. 실제 효용은 별도 사용자 사례로 검증한다.
5. 검토 후 새 버전 패키지를 색인에 등록한다. 도구 권한 확장은 별도 검토한다.
6. 실행 원장의 버전별 시도/근거/실행 실패와 사용자 피드백을 보고 개선한다. 호출 횟수가 많거나 verified가 많다는 것만으로 좋은 스킬로 판단하지 않는다.

현재 후보 생성·승격은 명시적인 코드 리뷰 절차다. 자동 스킬 학습/승격 서비스가 구현됐다는 의미는 아니다.

## 검증과 운영 관찰

- 변경 종류: agent 기능 추가. 확인된 운영 장애 없음. 이번 검증은 로컬 합성 입력만 사용한다.
- 불변 조건: 기존 사용자 수정 보존, 비활성 시 기존 동작 유지, 스킬이 권한을 확대하지 않음, 재개 시 버전/예산 보존, 근거 없이 검사 통과하지 않음.
- 결정적 테스트와 회귀 검증: `./gradlew test --tests 'com.gahyeonbot.services.ai.agent.*' --tests 'com.gahyeonbot.services.ai.agent.skills.*' --tests 'com.gahyeonbot.adapters.agent.AdmissionControlledConversationAdapterTest'`
- 실제 공통 런타임 통합 시나리오: 선택→네이티브 도구→완료, 조기 완료 교정/버퍼링, step 한도, 권한 밖 도구 거부, 선택/실행 혼합 배치 거부, 실행 중 취소, 비활성 경로, 예보 없음, 승인 후 MCP 바인딩 호출, 백그라운드 재개, 기능 비활성화 후 재개 차단, 완료 커밋 취소. 모델·외부 서비스·MCP는 테스트 대역이며 운영 정확도 검증이 아니다.
- 회귀 게이트: `bash scripts/run_ai_quality_gate.sh`
- 배포 후 관찰할 신호: 스킬 id/version, 시도·근거·verified 수, 관련 실행의 terminal 상태, 승인 누락/권한 위반 횟수. 원문 대화/결과는 스킬 저널에 기록하지 않는다.
- 관찰 창: 배포가 승인되면 최소 30분, 관련 요청 30건 이상. 트래픽이 없으면 검증 불가로 기록한다.
- 되돌림 기준: 승인 없는 도구 실행, 다른 사용자 범위 접근, 취소 후 완료, 버전 불일치 재개는 1건이라도 기능 중단 검토. 실제 롤백은 명시적 권한이 있을 때만 한다.
- 운영 검증 상태: 미배포, 운영 적격 요청 수 미측정.
