# Looking Glass Go 렌더링 비용 최적화

v016은 v015 방과 캐릭터를 유지하고 렌더링 영역과 캐시 재생 수명만 바꾼 후보입니다. 설정은 `config/looking-glass-room-v016.json`, 이전 설정은 `looking-glass-room-v015.json`입니다. 사람의 시각 검수는 아직 받지 않았습니다.

## 렌더링 영역

기존 800×629 화면에서 presenter가 사용하던 영역은 `[302, 91, 553, 537)`의 251×446 픽셀입니다. 새 `portrait-v001` 프로필은 카메라 원점과 회전을 유지한 채 filmback과 광학 중심을 조정해 이 영역을 직접 렌더링합니다. Metal IOSurface의 행 정렬 때문에 실제 버퍼는 252×448이며 오른쪽 한 열과 아래 두 행은 출력에서 제외합니다.

렌더 픽셀 수는 503,200에서 112,896으로 77.56% 줄어듭니다. 최종 quilt는 기존과 같은 2728×2724, 11×6, 66개 시점입니다. 시점별 tile도 248×454로 유지합니다. 배경 WPO, 캡처 깊이 0.12, 원본 캐릭터 재질과 애니메이션은 유지합니다. 화면 밖 오브젝트도 그림자 등으로 필요할 수 있으므로 이 변경이 방의 모든 외부 오브젝트를 제거한다는 뜻은 아닙니다.

프로필을 캐시 키에 포함하므로 기존 800×629 캡처와 혼용하지 않습니다. 기존 설정은 기존 캐시 키를 그대로 사용합니다.

## 캐시 재생과 프로세스 수명

120개 pose가 이미 있으면 presenter만 실행합니다. 이 경로는 IOSurface 공유 메모리를 열지 않으며 Unreal을 시작하지 않습니다. 캐시 크기와 LZ4 복원을 검사하고 손상된 캐시는 오류로 종료합니다.

캐시를 새로 만들 때는 canonical launcher로 Unreal을 시작합니다. presenter가 캐시를 복원해 실제로 첫 pose를 표시한 뒤 준비 파일을 씁니다. 방 launcher는 이 신호를 받은 뒤 자신이 시작한 렌더러 프로세스 그룹을 종료하고 presenter만 유지합니다. 렌더러가 준비 신호 전에 종료하면 실패로 처리합니다. 종료가 지연되면 5초 후 해당 그룹을 강제 종료합니다.

이는 4초짜리 idle 캐시 미리보기의 최적화입니다. 실시간 대화 동작이나 날씨 변화가 캐시에 반영되는 기능을 구현한 것은 아닙니다.

## 검증

실제 장치 `LKG-E08611`에서 새 캐시 생성, 렌더러 종료 이후 재생, 캐시만 사용하는 재시작을 확인합니다. 프레임 시간과 시간차 화면 캡처는 `artifacts/looking-glass-room-v016/`에 기록합니다. 평면 스크린샷은 실제 광학 잔상 개선의 증거로 사용하지 않습니다.

최초 251픽셀 버퍼는 Metal 행 정렬 검증에 실패해 폐기했습니다. 정렬을 적용한 후보만 비교 대상으로 사용합니다. GitNexus 인덱스에 최신 presenter와 방 launcher가 없어 실제 diff와 호출부를 직접 검토했습니다.
